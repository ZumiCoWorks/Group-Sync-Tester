# AFDA Continuum POC — Demo Script

## Preparation

- Confirm the page displays the Proof of Concept and demo banners.
- Set `NEXT_PUBLIC_CONTINUUM_DEMO_MODE=true`.
- Configure the four existing-module URLs.
- Use only the supplied fictional DEMO records.

## Ten-minute walkthrough

1. Home: explain the Pre-Continuum → Continuum → Post-Continuum operating story.
2. Ventures: open “Neighbourhood Futures” and show the immediate “Now” priorities.
3. Persona: switch between Student, Junior Tutor, Lecturer, Registry-capable Staff and Admin; show that visibility and next actions change but no trusted role is written.
4. Production activity: show Schedule, Group Sync and WorkSuite ownership and open one separate module.
5. Learning: compare the Teams-sourced assessment with the native Continuum specialist review and explain submitted/finalised/released separation.
6. Integrations: load the fictional import, inspect mapping, validate, resolve the unmatched demo student and confirm the preview.
7. Registry: show held records, source lineage and a fictional CSV export.
8. Administration: explain baseline roles, scoped capabilities, expiry, operational ownership and the controls still required for a pilot.

## Questions to capture

- Who owns Venture creation and membership?
- Who may appoint assessors, finalisers and moderators?
- Which existing role should baseline Registry-capable staff use?
- What CARS file contract and confirmation evidence are required?
- Which Microsoft permissions can AFDA approve?
- What is the smallest real pilot cohort and acceptable support model?

## Closing statement

The POC proves the workflow and deployment boundaries. It does not contain real academic records or a production authorisation bypass. The next investment is a controlled pilot foundation, not more fictional screens.
